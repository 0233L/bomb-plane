# xiaoheihe —— 炸飞机（小黑盒离线版）

这是网页版 [`public/`](../public/) 的移植副本，使用 hb-sdk（Vite）工程打包，
运行在小黑盒 App 的小程序沙箱里；**不是**微信小程序，和 `miniprogram/` 无关。

当前版本是**离线版**：没有服务器、没有网络请求，只保留两种玩法：

- **人机对战**：本地运行 `ai.js` 的浏览器副本；
- **同屏双人**：两人共用一台设备，步数不落后时可在顶部主动切换玩家；
  领先时悬浮条会变醒目，提醒把设备交给对方。

对局中点「返回菜单」不会直接销毁本局，而是先暂停：首页会出现「🕹 继续上局」卡片，
可以回来接着部署或对战（同屏双人会先显示不透明交接页，确认当前操作玩家）。
房间只存在内存里，刷新页面后不会保留。每局正常结束后会自动保存一条对战记录
（最近 20 局，只存在本机），首页「📜 对战历史」可以查看和清空。

对战页对方棋盘标题右侧有「二次确认」勾选框：勾选后普通探测要连点同一格两次
才生效，第一次只高亮目标、点别的格子会改选；道具流程不受影响。默认关闭，
选择会记住。同屏双人的两位玩家**分开记忆**（`bp_reveal_confirm_p0` /
`bp_reveal_confirm_p1`），换人后自动切换成当前玩家的设置；0 号位的选择还会
同步成设备默认，下次玩人机/联机时沿用。

网页版 `public/`、`server.js`、`ai.js` 仍然是在线联机版；网页版也已同步只读的
「📜 对战历史」（自动记录人机 / 联机对局，不提供清空和同屏双人）。

## 命令

```bash
npm install
npm run dev      # hb-sdk dev：Browser Mock + 真机扫码调试
npm run build    # 构建到 dist/（hb-sdk 自动注入 CSP 和 manifest）
```

发布相关命令（登录、绑定、权限、上传）：

```bash
npm run hb-sdk -- login
npm run hb-sdk -- remote bind <miniProgramId>
npm run hb-sdk -- remote permission list
npm run hb-sdk -- remote deploy --release-note "更新说明"
```

## 权限

只需要 `storage`（记住昵称、头像、主题等偏好）。
`network` 权限已移除：生产包不会申请网络，也不会连接任何服务器。
之前的联机版因为域名 `bomb-plane.onrender.com` 没有 ICP 备案被驳回，
所以改为离线版；将来要恢复联机，需要先完成备案再重新申请。

│       ├── local-server.js # 浏览器里的「服务器」：房间、判定、AI 调度、换人

## 离线版实现要点

- `local-server.js` 对外提供与 `ws.js` 的 `WSClient` 完全相同的接口
  （`on / once / off / emit / connected`），所以 `client.js` 里的连接事件、
  部署、开火、道具、结算逻辑几乎不用改。
- 对局进行中，飞机坐标只存在 `LocalServer` 内存里，界面只拿到「某格揭示后
  是什么」，与联机版的服务器权威模型一致；只有对局结束时才把终局棋盘
  快照写进本机历史（不经过网络）。
- 同屏双人：
  - 服务器记录 `activeSeat`（当前能行动的人）和 `clientSeat`（界面显示谁的视角）；
  - **不强制换人**：步数落后时继续行动追平；步数相等时顶部半透明悬浮条
    询问是否切换；步数领先时悬浮条变醒目（不透明度拉满）并提示切换；
  - 只有玩家点「切换玩家」才弹出全屏不透明的交接页；接手方点按钮后发
    `passReady`，服务器校验（部署已确认 / 步数不落后）后切换座位，
    并发送该座位的完整快照（复用联机版的 `reconnected` 事件）；
  - 悬浮条由 `dockSwitchBar()` 停靠在对战页的 `#switch-slot` 里，和玩家信息栏
    一起包在 `.battle-sticky-top` 中整体吸顶：悬浮条永远在信息栏上方，滚动时
    不会互相重叠，也不会挡住「返回菜单 / 规则」；
  - 部署草稿不写入 localStorage，换人后不会看到上一位玩家的布局；
  - 再来一局不强制换人：设备在谁手里，谁先重新部署。
- 返回菜单 = 暂停：`suspendRoom` 把房间标记为 `suspended` 并暂停 AI 定时器，
  首页显示 `roomSuspended` 摘要和「继续上局」卡片；`resumeRoom` 校验座位后
  发送快照恢复，AI 对局重新排程，同屏双人必须先经过不透明交接页确认操作玩家。
  暂停期间任何揭示/道具/部署请求都无效；已结束的对局直接清房（战绩已保存）。
  未确认的部署草稿只放在内存 `state.resumeDraft`，不写入宿主存储。
- 刷新页面回到首页：本地对局只存在内存里，无法续局（符合预期）。
- 探测二次确认：`state.revealConfirm` / `state.revealPending`，存储键
  `bp_reveal_confirm`（已加入 `HOST_STORAGE_KEYS`，iOS 刷新后也能恢复）；
  开启时第一次点未知格只记目标并画虚线框，第二次点同一格才 `reveal`，
  点别的格子改选；道具选区优先，完全不走这套逻辑。
- 人机对战：AI 思考延迟 0.8–1.5 秒；AI 自动部署、自动投「再来一局」票。
- 对战历史：`gameOver` 时写入 `bp_match_history`（最近 20 局，新记录在前），
  保存时间、类型、玩法、地图、双方昵称/头像、步数、赢家，以及双方的终局棋盘
  快照（飞机布局 + 打过的格子）。快照只在本机保存，不会发送到任何服务器。
  存储失败或坏数据不会影响对局结算和首页启动。
  首页「📜 对战历史」弹窗可查看、清空；确认弹窗的 z-index 更高，会盖在历史弹窗上面。
  点有棋盘快照的记录可以看双方终局棋盘（机头/机身、已探测格、摧毁格）；
  旧记录没存棋盘，仍能在列表里查看，但会标注「旧记录未保存棋盘」。

## 与网页版的差异

- 删除联机入口（创建/加入房间、最近房间、观战、访客统计、连接提示）；
- 新增「同屏双人」入口和交接页；
- 新增「对战历史」入口（只保存在本机，可一键清空）；
- `network` 权限移除，`ws.js` 不再导入；
- 返回菜单、改昵称使用页面内弹窗（iOS 会屏蔽 `confirm` / `prompt`）；
- App 安全区留白（`viewport-fit=cover` + `viewport.getWindowInfo()` 兜底）；
- 昵称基础内容过滤，随机昵称也保证不超过 12 个字符；
- 同屏双人里 2 号位改名/换头像不会覆盖设备主人的本地记忆。

更多平台说明见 [CLI 指南](https://docs.xiaoheihe.cn/hb_sdk/guide/cli) 和
[SDK 文档](https://docs.xiaoheihe.cn/hb_sdk/)。
