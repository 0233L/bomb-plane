# 小黑盒离线版（本地人机 + 同屏双人）

## Goal

小黑盒 `network` 权限因 `bomb-plane.onrender.com` 无 ICP 备案被自动驳回后，
按用户决定把 [`xiaoheihe/`](../../../xiaoheihe/) 改为**纯离线小程序**：

- 不连接任何服务器，删除 `network` 权限；
- 保留原有玩法（经典/道具、S/M/L 规格、规则、主题、昵称、头像）；
- 提供「🤖 人机对战」（本地 AI）和「👥 同屏双人」（一台设备轮流操作）；
- 初版不修改 `public/`、`server.js`、`ai.js`、`miniprogram/`（网页版保持联机不变）；
  2026-10-23 用户追加网页版只读对战历史，见「追加需求」。

## Requirements

### 功能

1. **首页**：昵称、头像、经典/道具玩法、地图规格、规则、主题、人机对战、同屏双人。
   移除创建房间、房间号加入、最近房间、访客统计等联机入口。
2. **人机对战**：完全在本地运行，AI 部署与走棋复用 `ai.js` 的算法（打包进小程序）。
3. **同屏双人**：一台设备两人轮流操作；每次行动结束后显示不透明的「交接设备」页，
   避免对方看到自己的飞机部署；双方各自部署 3/4/6 架飞机后开战。
4. **对局能力**：部署/取消确认、经典揭示、全部 6 个道具、步数规则、机头胜负、
   累计比分、再来一局、右键/长按标注、刷新后回到首页（离线房间不跨刷新恢复）。
5. **平台适配**：保留小黑盒安全区、宿主存储（主题/昵称/头像/规格记忆）、
   自定义弹窗、动态棋盘尺寸。

### 约束

- 初版只改 `xiaoheihe/`；追加网页版历史时只改 `public/` 的历史相关文件，
  `server.js`、`ai.js`、`miniprogram/` 始终不改。
- 不把服务器地址、WebSocket、`network` 权限留在发布包里。
- 代码简单直观、中文注释，符合用户阅读习惯。
- 不加入充值、支付、付费解锁等商业化功能。
- 不执行 git commit（除非用户明确要求）。

## 追加需求（2026-10-23）

- 网页版同步「📜 对战历史」：自动记录人机与联机对局，首页只读查看最近 20 局。
- 不加入同屏双人入口，不提供清空操作，不改服务器协议。
- 历史记录扩展终局棋盘回看（只读、非逐步复盘）：只从本机存储读取，不新增
  服务器协议、不请求网络；旧记录保持可列但不可点。

## 追加需求（2026-10-23 第二批）

- **换人条布局**：同屏双人顶部的换人悬浮条必须排在玩家信息栏上方，两者一起
  吸顶，滚动时不能互相重叠，也不能被屏幕顶部裁掉。
- **离线续局**：对局中点「返回菜单」改为暂停房间，首页出现「🕹 继续上局」；
  可继续部署中的草稿或对战中的对局。同屏双人继续前必须先显示不透明交接页，
  由当前操作玩家确认身份，避免布局泄露。只支持部署中 / 对战中；已结束的对局
  不续（战绩已保存）；刷新仍回到首页（房间只在内存里）。
- **探测二次确认**：网页版和小黑盒版的敌方棋盘标题右侧新增「二次确认」勾选框。
  勾选后每次普通探测都要连点同一格两次（第一次只高亮目标，点别的格子改选）；
  道具流程完全不变。默认不勾选，选择永久记忆。

      继续后步数、棋盘、金币、未确认的部署草稿都恢复。

      已结束对局和刷新页面不出现续局卡。

- [x] 同屏双人两位玩家的二次确认偏好分开记忆；换人后自动切换成当前玩家的设置，
      1 号位不会覆盖设备主人的选择。

## Risks

1. 同屏双人的信息隐藏：必须使用不透明交接页，且切换座位时清空部署草稿。
2. `ai.js` 依赖 Node 的 `require` / `process.env`，复制到浏览器需适配包装层。
3. 手机 WebView 上 AI 预计算（66,816 组合）可能有启动耗时，需观察是否可接受。
4. 离线版无法使用原有房间历史/断线重连，刷新即结束本地对局（符合预期，需在文案说明）。
